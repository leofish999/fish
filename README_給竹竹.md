# MISSION POSSIBLE｜ARCADE V2（分段版）

## 這版改了什麼
- 電玩風深藍＋霓虹青／金黃，手機響應式介面。
- 四關分別 10、10、15、15 分鐘；**由主持人投影 host.html 統一倒數**。
- 主持人可開始、暫停、繼續、結束、重設倒數；講解期間不計時。
- 每關有獨立通行碼，必須依序解鎖；不可提前闖關。
- 每次點選會先顯示確認頁，按「LOCK IN」才永久鎖定；刷新頁面可續玩已鎖定的進度。
- 每關結束只顯示 RESULT SEALED，不顯示單關分數／評級／結局。
- 四關完成後，輸入主持人最後公布的揭曉碼，才顯示各關與總分。
- 主持人頁面可匯入隊伍 JSON 並產生總分排行榜，支援匯出 CSV。
- 移除合作卡加分與介面；原四關分支與配分不變。

## 檔案怎麼分
```
index.html                  學生遊戲頁
host.html                   主持人計時器＋通行碼＋排行榜
assets/css/style.css        電玩美術樣式
assets/js/config.js         【先修改這裡】關卡時間、通行碼、揭曉碼
assets/js/main.js           玩家畫面與流程
assets/js/engine.js         分支計分與隱藏結局
assets/js/storage.js        手機本機存檔與 JSON 匯出
assets/js/host.js           主持人倒數與匯入排行榜
data/mission1.json          交通劇情
... mission2～4.json        選手村、團膳、文化夜市劇情
```

## 先做的三件事
1. 修改 `assets/js/config.js` 的五組代碼；勿在活動前公開代碼。
2. 在目錄執行 `python3 -m http.server 8000`，開啟 `http://localhost:8000/` 測試玩家頁、`http://localhost:8000/host.html` 測試主持人頁。不要直接雙擊 HTML。
3. 確認測試後將整個資料夾部署到 AWS 靜態網站服務（S3/CloudFront 等皆可），保留相對路徑。

## 現場操作
- 開場前：主持人打開 `host.html` 投影；學生在 `index.html` 登入組別。
- 第一關：公布 M01 通行碼，同時啟動 10 分鐘倒數。後三關依序 10、15、15 分鐘。
- 每關結束：主持人結束倒數，學生完成後停在 `RESULT SEALED`，講解時不開下一關。
- 下一關：講解後公布新的通行碼；學生只能按順序進行。
- 四關結束：隊長匯出 JSON 交給主持人；主持人匯入 `host.html`，最後公布揭曉碼並展示排名。

## 必須知道的限制
- **沒有後端，因此主持人按「時間到」不會遠端自動鎖住所有手機**；需要口頭控場。計時器只是主持人本機／投影畫面。
- 前端通行碼只是活動流程控管，無法防止懂技術的玩家檢視原始碼；也不能嚴格驗證截止時間。
- 手機成績存在 localStorage，不會跨裝置同步；若使用無痕、清除資料或換手機，可能遺失。
- 主持人匯入的檔案不會永久儲存，請結算後立即匯出 CSV。
- 最終揭曉碼也屬前端控場，並非強安全機制。
- 任何 AWS 主站故障的 Google 表單備援，需要另外建置；此包沒有宣稱自動切換或同步。

## 測試重點
- 各關通行碼能否解鎖；未完成 M01 不可進 M02。
- 每階段鎖定後重新整理仍可續玩，不能回溯。
- M03 第一階段 C 立即 0 分結束。
- M04 脫窗線可拿高分；隱藏結局正確。
- 四關前不能看到分數；揭曉碼後才顯示。
- 主持人倒數暫停／繼續正確；匯入 JSON 排行與匯出 CSV 正常。

此為可部署的前端原型，正式活動前仍須以手機實機走完至少一輪。
